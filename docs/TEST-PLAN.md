# テスト計画

## 学習フロー

- ホームから各10ステージを開始できる。
- 各問題形式で回答し、正解・不正解の表示を確認できる。
- ヒントを使っても回答を続けられる。
- 答えと解説を見た問題は正答として記録されない。
- 最終問題から結果画面へ進める。
- 結果画面から再挑戦・苦手特訓・ホームへ進める。

## 採点

- select/classify：登録IDと一致したときだけ正解。
- pair/relation：両端のIDと向きが一致したときだけ正解。
- strip：順番に関係なく、正しい語句集合が一致したときだけ正解。
- repair：登録された許容解答を受け入れる。
- reorder：正しい語句順を受け入れる。
- compose：条件達成を表示する。機械判定だけで文章全体の自然さを保証しない。

## 保存

- リロード後も回答履歴・設定が残る。
- JSON書き出しができる。
- 書き出したJSONを読み込める。
- 不正なJSONを読み込んでも既存記録を失わない。
- 記録初期化は確認後に行われる。

## 表示とアクセシビリティ

- 幅375px程度のスマートフォンで横スクロールやボタンの重なりがない。
- タブレット横向きとPCで問題文・操作・進捗が見やすい。
- 主要操作はタップで完結する。
- 色だけで役割や正誤を伝えない。
- prefers-reduced-motionに対応する。
- ナビ画像が読み込めなくても学習を続けられる。

## 文法の品質

- 「が・は・も」だけを主語判定の規則にしない。
- 主語と述語の関係が問題文の意味と一致している。
- 修飾語が詳しくする相手が明確である。
- 複数の修正案がある場合は許容解答として登録する。
- 語順問題では文法的に成立し、意図した関係が分かる文を用いる。
- 自作文は機械判定の限界を明記し、条件達成と文章の自然さを区別する。
